# Daniel's 개인 비서

일정·할 일·메모·브리핑을 한 화면에 모은 모바일 우선 개인 비서 대시보드입니다.
빌드 과정이 없는 정적 웹앱(PWA)이라 어디에든 올려 두고 휴대폰 홈 화면에 설치해 쓸 수 있습니다.

## 화면 구성

| 탭 | 내용 |
| --- | --- |
| **오늘** | 통합 대시보드 — 오늘 할 일 · 예정 일정 · 중요 알림 요약, 빠른 입력, 미완료 항목 추적, 오늘의 브리핑 |
| **할 일** | 범위(진행 중·오늘·이번 주·지연·날짜 없음·완료), 중요도, 태그 필터 |
| **캘린더** | 월간 달력 + 선택한 날의 일정과 할 일 마감. 여러 날 일정은 기간의 모든 날에 표시 |
| **메모** | 제목·내용·태그 전체 검색(검색어 강조), 태그 필터, 상단 고정 |
| **브리핑** | 매일 자동으로 만들어지는 오늘 요약 + 기술 브리핑 보관함 |

## 주요 기능

### 자연어 할 일 입력

입력창에 평소 말하듯 적으면 날짜·시간·중요도·태그·반복을 알아서 분리합니다. 입력하는 동안 해석 결과가 바로 아래에 미리 보입니다.

| 입력 | 해석 |
| --- | --- |
| `내일 오후 3시 분기 보고서 제출 !중요 #업무` | 내일 15:00 · 중요 · #업무 |
| `모레까지 견적서 회신` | 모레 마감 |
| `다음 주 수요일 워크숍 준비` | 다음 주 수요일 |
| `11월 20일 계약 갱신`, `12/25 선물 준비`, `25일까지 카드값 납부` | 해당 날짜 |
| `3일 후 택배 확인`, `월말까지 정산` | 상대 날짜 |
| `매주 월요일 주간 보고` | 매주 반복(완료하면 다음 회차 자동 생성) |
| `11월 20일~22일 부산 출장`, `20일부터 22일까지 워크숍` | 기간(여러 날) 일정 |
| `매주 목요일 밤 11시 세차`, `매월 25일 월세`, `매년 3월 1일 결혼기념일` | 반복 일정(일정 모드) |
| `내일부터 3일간 휴가`, `20일부터 2박 3일 제주 여행` | 시작일부터 며칠간 |
| `긴급 서버 점검`, `서버 점검 !!`, `책 반납 !낮음` | 중요도 |

수식어 없는 1~6시는 오후로 봅니다(`3시 회의` → 오후 3시). 시간만 적으면 오늘, 이미 지난 시각이면 내일로 잡습니다.
기간을 적으면 일정은 시작일~종료일로, 할 일은 마지막 날을 마감으로 저장합니다. 일정 창에서는 **종료일**을 직접 고를 수 있습니다.
일정도 **매일·매주·매월·매년** 반복할 수 있고(일정 창의 「반복」, 「반복 끝」), 반복 일정의 한 날짜를 열어 **이 날만 삭제**할 수 있습니다. 매월 31일처럼 그달에 없는 날짜는 건너뜁니다.

### 미완료 항목 추적

마감이 지난 할 일은 대시보드의 **미완료 항목 추적**에 며칠 지연됐는지와 함께 모이고, `오늘로 / 내일로 / 다음 주로` 한 번에 옮길 수 있습니다. 미룬 횟수와 원래 마감일이 기록되며, 3번 이상 미룬 항목은 중요 알림에 올라옵니다.

### 중요 알림

지연된 할 일, 오늘·내일 마감인 중요 항목, 1시간 안에 시작하는 일정, 여러 번 미룬 항목을 한곳에 보여 줍니다.

### 매일 브리핑

오늘의 핵심 3가지, 오늘 일정·할 일, 미완료 항목, 이번 주 다가오는 마감, 어제 완료한 일, 최근 24시간에 쓴 메모(없으면 고정 메모)를 요약합니다. 그날 처음 열면 대시보드 위쪽에 "새 브리핑"으로 표시되고, **복사** 버튼으로 마크다운 텍스트를 가져갈 수 있습니다.
정기 기술 브리핑은 `#브리핑` 태그를 붙인 메모로 저장하면 **기술 브리핑 보관함**에 모입니다.

### 알람

할 일·일정마다 **정시, 5·10·15·30분 전, 1·2시간 전, 하루 전** 알람을 고를 수 있습니다(편집 창의 「알람」). 빠른 입력에 `10분 전 알림`, `1시간 전 알람`, `하루 전 알림`, `정시 알림`이라고 써도 됩니다. 시간이 없는 할 일·종일 일정은 그날 오전 9시를 기준으로 합니다.

- **설정 → 알림 → 이 기기에서 알림 받기**를 켠 기기는 앱이 꺼져 있어도 받습니다. Cloudflare Worker 알림 발송기([cloudflare/](cloudflare/README.md))가 1분마다 확인해 보냅니다.
- 앱이 켜져 있으면 앱도 직접 울립니다. 같은 알람은 하나로 합쳐져 두 번 울리지 않습니다. 앱을 늦게 열면 15분 안에 지난 알람까지 알려 줍니다.

### 기기 간 동기화 (PC ↔ 폰)

데이터를 본인의 GitHub **비공개** 저장소에 있는 JSON 파일(`data/assistant.json`) 하나에 함께 저장해, 연결한 모든 기기가 같은 내용을 봅니다. 별도 서버나 유료 서비스는 쓰지 않습니다.

1. **PC에서 한 번**: GitHub에서 fine-grained 토큰을 만듭니다. 저장소는 데이터용 비공개 저장소 하나만, 권한은 **Contents: Read and write**만 줍니다. 앱의 **설정 → 기기 간 동기화**에 붙여 넣고 **연결**합니다.
2. **폰**: PC 설정 화면의 **다른 기기 연결**을 눌러 QR 코드를 띄우고, 폰 앱의 **QR 코드로 연결**로 찍습니다. 연결 링크를 복사해 폰에서 열거나 토큰을 붙여 넣어도 됩니다.

- 앱을 열 때, 무언가 고친 뒤 2초 후(그 전에 앱을 닫으면 닫을 때), 그리고 열어 둔 동안 5분마다 자동으로 동기화합니다.
- 연결하기 전 각 기기에 있던 데이터는 합쳐집니다. 같은 항목을 두 기기에서 고치면 더 나중에 고친 쪽이 남고, 지운 항목은 다른 기기에서도 지워집니다.
- 여러 기기가 동시에 저장하면 GitHub가 한쪽을 거절하고(파일 버전 확인), 그 기기가 다시 읽어 합친 뒤 저장합니다.
- 이름·화면 테마는 기기마다 따로입니다.
- 토큰은 각 기기의 브라우저에만 저장되고 데이터 파일에는 들어가지 않습니다. QR 코드와 연결 링크에는 토큰이 들어 있으니 다른 사람에게 보여 주지 마세요.
- 토큰이 만료되면 동기화가 멈추고 설정 화면에 오류가 보입니다. 새 토큰으로 다시 연결하면 됩니다.

### 아침 브리핑 알림 (매일 오전 8시)

동기화된 데이터로 매일 아침 8시 정각에 **오늘 할 일·미완료 업무·메모** 요약을 알림으로 보냅니다. 알림을 누르면 브리핑 화면이 열립니다.

- Cloudflare Worker 알림 발송기([cloudflare/](cloudflare/README.md))가 Web Push로 보냅니다. 내용은 기기별로 암호화되어 전달됩니다.
- 데이터 저장소의 GitHub Actions(`morning-briefing.yml`)는 예약 실행을 끄고 수동 실행(예비용)만 남겨 두었습니다.
- 알림 받을 기기마다 **설정 → 알림 → 이 기기에서 알림 받기**를 누릅니다.
  - iPhone·iPad: Safari에서 **홈 화면에 추가**로 설치한 앱에서만 됩니다(iOS 16.4 이상).
  - Android·PC: Chrome·Edge에서 됩니다. PC는 브라우저가 켜져 있을 때 받습니다.
- **지금 브리핑 알림 보기**로 이 기기에서 알림이 어떻게 보이는지 바로 확인할 수 있습니다.
- 알림 서명 키(VAPID)는 처음 알림을 켠 기기가 만들어 동기화 데이터에 함께 저장합니다. 그래서 데이터 저장소는 반드시 비공개여야 합니다.

### 데이터와 백업

- 동기화를 연결하지 않으면 데이터는 **이 기기의 브라우저(localStorage)에만** 저장됩니다.
- iPhone은 홈 화면에 설치한 앱과 Safari의 저장 공간이 따로입니다. 동기화를 연결하면 양쪽 모두 같은 내용을 봅니다.
- 동기화 없이 앱을 삭제하거나 브라우저의 사이트 데이터를 지우면 내용도 함께 지워집니다.
- **설정 → 데이터**에서 JSON 백업 내보내기/가져오기를 할 수 있습니다. 동기화 중에 백업을 가져오면 연결된 모든 기기가 백업 내용으로 바뀝니다.
- **마크다운 가져오기**: 기존 할 일 목록을 `- [ ] 내일까지 견적서 회신 #업무` 형태로 붙여 넣으면 한꺼번에 등록됩니다. Obsidian Tasks 표기(`📅 2026-11-20`, `⏫`, `🔁 every week`)도 인식합니다.
- **마크다운 내보내기**: 할 일과 메모를 Obsidian에서 바로 열 수 있는 `.md` 파일로 저장합니다.

## 실행

```bash
npm start
```

`http://localhost:8080` 에서 열립니다(파이썬 내장 서버 사용, 별도 설치 없음).

```bash
npm test
```

자연어 파서, 저장소·병합, 브리핑·알림 내용, 마크다운 변환, 연결 링크 해석의 단위 테스트를 실행합니다(Node 20 이상).

## 휴대폰에 설치하기

정적 파일만으로 동작하므로 GitHub Pages 등 HTTPS 정적 호스팅에 그대로 올리면 됩니다.

- **GitHub Pages**: 이 저장소는 `gh-pages` 브랜치의 내용을 그대로 게시합니다. `main`을 고친 뒤 같은 커밋을 `gh-pages`에도 푸시하면 1~2분 안에 사이트에 반영됩니다.
- 배포된 주소를 휴대폰 브라우저로 연 뒤 **홈 화면에 추가**(iOS Safari: 공유 → 홈 화면에 추가 / Android Chrome: 메뉴 → 앱 설치)를 누르면 앱처럼 실행되고 오프라인에서도 열립니다.

## 앱 업데이트(배포)

1. 코드를 고친 뒤 `node tools/bump-version.mjs`로 버전을 올립니다. `index.html`의 모든 스크립트 주소(`?v=…`)와 `version.json`이 함께 바뀝니다.
2. `npm test`가 통과하면 `main`과 `gh-pages`에 푸시합니다.

- 각 기기는 앱을 열 때마다 서버에 새 파일이 있는지 확인하므로, 배포 뒤 앱을 열면 바로 새 버전이 뜹니다.
- 이미 열려 있는 앱도 앱으로 돌아올 때(그리고 30분마다) `version.json`을 확인해 새 버전이면 스스로 새로 고칩니다. 글을 쓰는 중이거나 설정·편집 창이 열려 있으면 끝날 때까지 기다립니다.
- 할 일·일정·메모는 앱 코드와 따로(각 기기의 브라우저 저장소와 데이터 저장소) 저장되므로 업데이트해도 그대로입니다.
- 한동안 옛 버전으로 남은 기기가 있어도, 새 버전이 데이터에 추가한 내용을 지우지 않고 그대로 둡니다. 데이터 형식을 호환되지 않게 바꾼 경우(`format` 증가)에는 옛 버전 기기가 동기화를 멈추고 업데이트하라고 알립니다.

## 구조

```
index.html              앱 뼈대(상단 바, 하단 탭)
css/styles.css          스타일(라이트/다크)
js/app.js               화면 렌더링과 상호작용
js/store.js             상태 저장·조회, 기기 간 병합 규칙
js/sync.js              GitHub 저장소를 통한 기기 간 동기화
js/push.js              아침 브리핑 알림 켜기·끄기(Web Push)
js/qr.js                다른 기기 연결용 QR 코드 만들기·읽기
js/b64.js               Base64 도우미
js/nlp.js               한국어 자연어 입력 파서
js/briefing.js          매일 브리핑·아침 알림 내용 생성
js/markdown.js          마크다운 가져오기·내보내기
js/dates.js             날짜 유틸리티
sw.js                   오프라인 캐시, 알림 표시(서비스 워커)
tools/send-briefing.mjs 아침 브리핑 알림 보내기(GitHub Actions에서 실행)
tools/bump-version.mjs  배포 버전 올리기
version.json            배포된 버전(열려 있는 앱이 업데이트 여부를 확인)
vendor/                 QR 코드 라이브러리(원본 그대로, 라이선스 포함)
manifest.webmanifest    PWA 설정
tests/                  단위 테스트
```
